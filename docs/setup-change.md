# One-step screenshot folder setup

The user explicitly requested an easier setup that changes both Screenshot Tray's watched folder and the macOS screenshot destination, and required the original app to be pushed first. Original version committed and pushed to origin/main as 375af90 before any implementation changes.

Use one clearly labeled Choose Screenshot Folder action and a native picker whose confirmation says Set Screenshot Folder. Explain before confirmation that this changes the Mac's screenshot save location. On success, open the tray directly; no separate screenshot-toolbar setup is required. Settings provides the same change action.

Keep sandboxing. Add only the com.apple.screencapture shared-preference read/write exception documented by Apple. Use Core Foundation preferences to update the legacy location/target keys and modern location-screenshot/target-screenshot keys, setting file capture to the selected folder. The modern keys were confirmed in the installed Apple screencaptureui binary on macOS 27. Screenshot preference keys are undocumented; future OS compatibility is a limitation. Do not write recording-specific keys, formats, names, capture shortcuts, or take a screenshot. On older macOS releases with a shared save destination, changing that legacy destination may also affect recordings. Do not request Screen Recording, Accessibility, admin access, run shell commands from the app, or restart the menu bar.

Validate the selected folder is a directory on a writable volume and is writable by the current process. The selected-folder entitlement/bookmark is now read/write so this check is meaningful in the sandbox; a read-only extension would reject every destination. Do not write test files or change screenshot files. Prepare the folder bookmark before changing preferences. Update only the four screenshot destination keys, synchronize and read back; rollback on failure. Persist the folder bookmark and replace the watcher only after success. Cancel/error leaves the prior watched folder intact and shows a useful message.

Execution: add failing tests for destination updates and rollback, implement the preference adapter and transaction, simplify setup/settings UI, update docs, rebuild and run all checks. Isolated test preference domains avoid changing the user's screenshot destination during automated tests. Verify entitlement access with an isolated signed sandbox probe. End-to-end screenshot saving still requires a user screenshot.
